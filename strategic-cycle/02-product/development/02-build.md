# Build Phase — Development Cycle

**Inputs**: User stories, tech design, acceptance criteria  
**Outputs**: Committed code, passing unit tests, reviewed pull requests

Implement the user stories from the sprint backlog. Write clean, tested code following project conventions. Submit pull requests for peer review and address all review feedback before merging.

---

## Reference

### Participants
Software Engineers

### Activity
Write code, unit tests, peer review, integrate APIs

### Profile
| Dimension | Value |
|---|---|
| Execution / Exploration | 80% / 20% |
| AI Suitability | High |
| Key Methodology | TDD, Code Review (paired / async), Pair / Mob Programming, Trunk-Based Development, Conventional Commits |
| Key Decisions | Implementation approach, abstraction boundaries, naming, testing scope |
| Key Human Input | Edge case discovery, creative problem-solving, nuanced code review judgment, debugging intuition |
| KPIs | Cycle time (commit to deploy), code churn rate, PR merge rate, review turnaround time |

### Cycle I/O
| Direction | Partner | Signal | KPI |
|---|---|---|---|
| Incoming | Development (Tech Design) | User stories, tech design, acceptance criteria | Spec clarity score, criteria completeness |
| Outgoing | Development (Test) | Committed code, passing unit tests, reviewed PRs | PR merge rate, unit test pass % |
