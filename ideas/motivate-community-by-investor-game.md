# Community Support
if we stripe down the key input and output of the company/the software there are only two inputs
- tokens
- data (ideas, metrics, bug report)

and one output
- the software (and the metrics about how good, populate ,helpful it is) 


If we really want to run it as no-man company , we need input from commnities ( including the founder).  These input are not contributions, their are the milk and butter for the model (no man company) to run and the software to evolve. Contributors are the Investors of the company, they invest by their effort, resources or support tokens usage. 

If we think in company shares terms, the core is the share allocation algorithm. it need to motivate all forms of community contributions, either by direct token support, report a bug, share some ideas.

That's said, real shares invovles a lot of legal questions, not practical.  The only option I can think of is we publish it as an investing game, company is virtual, shares are also virtual, it's just a game.  We can model the whole product as an entertainment product of a game that connect to real life activities of invest effort in a virtual software company that delivers real software. 

To support the idea, we need a web based investor portal to mimic the investor experience. track the shares,  present key metrics movement (daily active users, workflow runs, npm downloads, github likes, issue backlog etc  ...).  Even if we dont publish it as a game, this metrics are also important for the software to evovle.

the only thing left is what is the return for the investors
